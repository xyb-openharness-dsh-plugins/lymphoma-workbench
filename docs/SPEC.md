## 1. 目标与非目标

**目标**：让刚确诊或正在治疗的淋巴瘤患者（及照护者），能在一个本地优先的工作台里回答四个问题：

1. 我得的是哪一型？依据是什么？（**分型**）
2. 现在用什么方案、走到第几周期、改过什么？（**治疗线**）
3. 治疗有没有效果？依据是哪次检查？（**疗效**）
4. 下次门诊要带什么、问什么？（**就诊准备**）

**非目标**：不做诊断工具、不做预后计算器、不做用药推荐、不做病友社区、不做医院系统对接。

## 2. 产品立场（D3，继承乳腺 D16）

1. **诊断、分期、疗效判读、处置归医生**。工作台只整理与呈现。
2. 用户的判断与担心按一条信息记录（`viewpoint`），固定标注「不是医生结论」，不进趋势、不进摘要事实区、不参与判断。
3. **分类变量不画趋势**：Deauville、Lugano 分期、ECOG、CTCAE 分级都按节点呈现。
4. **单次异常不构成结论**：LDH 升高、淋巴结略大、IgG 偏低，界面只陈述"记录到"，不给"提示/可能/建议"类判断。
5. **更正只新增版本**：亚型、分期、剂量、评估结论的修改都留旧值与日期，不覆盖。
6. **线索不是推荐**：临床试验模块不排序、不评分、不预测获益。
7. **缺省不猜**：未检测显示"未检测"，未写显示"原文未写明"，不补成阴性或正常。

| 真实患者数据上云 | 本地优先；云处理必须逐次明示 |

## 4. 信息架构

```
看板
我的分型 ── 分型档案 / 病理与分子 / 分期与病灶 / 会诊与二次意见 / 分型库
治疗历程 ── 当前方案 / 周期与用药 / 疗效评估      （页首为治疗线切换）
检查与指标 ── 血象 / 生化与免疫 / 感染监测 / 影像与 PET
病情一图秀
营养支持 ── 进食与体重 / 当下困扰
心理支持 ── 当下感受 / 生育与家庭
照护与症状 ── 感染与发热 / 症状与日常 / 血象与支持治疗
复诊准备 ── 复诊节奏 / 就诊准备 / 观察等待
临床试验 ── 线索 / 已收藏 / 入组问题
设置（弹窗，不占一级导航）
```

设计理由：

- **10 个一级页**（D27）：前 5 项是"我的病情"，后 4 项是"今天能做的事"，最后 1 项是"还能问什么"。顺序即优先级。
- **「我的分型」放第二位**，仅次于看板。乳腺工作台把"病情整理"放第二位；淋巴瘤的等价起点是分型，不是资料库。
- **「分型库」是分型页的第 5 个子页**（D17）：24 个亚型做对照，不进一级导航，因为它是"参考"而非"我的记录"。
- **「治疗线」是页首切换器，不是一级导航**（D24）：线是结构上的维度，用户仍然只有"治疗历程"一个入口。
- **「营养支持」「心理支持」「照护与症状」拆成三个一级页**（D27）：它们服务的是三种不同的当下困扰（吃不下 / 心里堵 / 身上不舒服），合并成"副作用与支持"会让人多点两次才能找到入口；分列后每页只有一个主题，也便于后续单独扩展。
- **「复诊准备」取代「随访与就诊」**（D27）：命名指向动作（准备），而不是抽象概念（随访）；一页之内既有节奏、又要带什么、还有观察等待。
- **「观察等待」放在复诊准备内**（D20 补充：惰性画像在**看板**出专属大卡），因为它是复查策略的一种，不是独立治疗。
- **设置不占一级导航**（沿用乳腺 D27）：配置不该占用一级注意力。

## 5. 四条主线

### 5.1 分型建立

`病理报告归档 → 抄录 IHC/FISH → 记录医生给出的分型与分期 → 标注"待确认项" → 会诊/修正留痕`

出口：一张能带去门诊的分型摘要（分型、分期、关键依据、未确认项）。

### 5.2 治疗执行

`治疗线 → 方案与周期 → 实际给药 → 延迟/减量原因 → 不良事件 → 支持用药`

出口：**按线分组的**周期表 + 一份"这次为什么改"的可追溯记录。换线新增一组记录，不覆盖上一线（D24）。

### 5.3 疗效回顾

`基线影像 → 中期评估 → 结束评估 → 随访影像`

出口：Deauville 节点序列 + 每次的原文结论 + 医生记录的整体反应（CR/PR/SD/PD）。

### 5.4 就诊准备

`勾选想问的事 → 记一条我的看法 → 导出 Markdown`

出口：两区分离的 Markdown（想问的事 / 我的看法与担心），带口径说明。

## 6. 淋巴瘤特有的六个场景

| # | 场景 | 工作台要给什么 | 明确不给什么 |
| --- | --- | --- | --- |
| L1 | 亚型复杂、报告看不懂 | 分型树定位 + 依据抄录 + 术语对照 | 不解释"这个亚型好不好治" |
| L2 | 惰性淋巴瘤观察等待 | 复查节点 + 观察期记录项 + 何时该问 | 不说"什么时候必须开始治疗" |
| L3 | 粒缺发热 | 联系团队的门槛写清 + 体温记录 | 不做分诊、不判断严重程度 |
| L4 | HBV 再激活 / PJP / IgG | 把筛查与随访结果排在一起 | 不给预防用药方案 |
| L5 | 长期口服 BTKi / 维持 | 用药起止、漏服、不良反应 | 不评价"能不能停" |
| L6 | 复发难治找试验 | 线索 + 入组问题（药名只作检索词） | 不推荐、不排序、不预测获益；不给药物说明 |

## 9. 风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 亚型覆盖过多 | 界面为 80+ 亚型做特例，维护崩 | 首批 24 项只是**数据行**（D17），不为任何亚型写专属页面；扩展只加行 |
| 分类变量被误画成趋势 | Deauville 被连成折线，读者以为"降到 2 就好了" | A11/A12 写死；图表只接受数值型指标 |
| 预后评分越界 | 工作台算出 IPI 并给"低危"结论 | D18 写死：无计算入口；A31 逐条检 |
| 观察等待被误解为"不治" | 患者焦虑或自行开始治疗 | 专页解释 + 复查节点 + 何时该问 |
| 试验模块变成推荐 | 排序、评分、"更适合你" | 不排序；固定免责；只给入组问题 |
| 药物资料越界 | 从"列药名"顺手扩成药物说明，抄到二手招募文案 | D22 写死：工作台不做药物说明，只指向说明书与研究方案 |

## 10. 术语

| 术语 | 本项目用法 |
| --- | --- |
| 亚型 | WHO-HAEM5 / ICC 下的具体诊断名称，如 DLBCL NOS |
| 线 | 治疗线（一线/二线/维持），不是"疗程" |
| 周期 | 一个给药周期（如 R-CHOP 21 天为一周期） |
| 评估 | 一次疗效判定（基线/中期/结束/随访） |
| 观察等待 | 惰性淋巴瘤暂不治疗、按计划随访的策略（W&W） |
| 完全代谢缓解 | PET-CT 的代谢反应结论（CMR），由读片医生给出 |
