# 提示词：从一个癌种到一套工作台（可复用）

用途：下一个「小 X 宝」病种（如肺癌、胃癌）启动时，直接拿这段当第一轮提示词。基于乳腺癌 v0.3 与淋巴瘤 v0.1 两次实践。

---

## 第一轮：侦察 + 骨架（不要写业务）

```
读 <上一个工作台目录> 的 README / docs/SPEC / docs/UI-DESIGN / docs/DEV-PLAN /
docs/HANDOFF，列出可直接复用的工程与设计资产、以及它的踩坑表。

然后在 ~/Downloads/<新病种>-workbench 新建项目：
1) 复制工程底座：package.json、VERSION、scripts/、lib/version.js、lib/layout.js、
   test/version.test.mjs、test/layout.test.mjs、dsh/index.js、lib/client.js、
   .gitignore、LICENSE、schema/README.md
2) 全文替换产品名、包名、环境变量前缀、目录名；VERSION 从 0.1.0 起
3) 处理 Logo：原件放 assets/brand/，裁出方形 mark（96/192）+ full + apple-touch-icon，
   同时复制一份到 prototypes/v0.1/assets/brand/（页面只引目录内相对路径）
4) 跑通 npm run check，贴真实输出
```

**不要**在这轮写页面、建表、接 DSH。

## 第二轮：领域差异表

```
读用户给的分类/指南/知识库。先产出一张"与上一个病种的根本差异"表，至少覆盖：
起点（分型/器官）、分期系统、疗效评估方式、治疗结构、特殊状态、主要并发症。
再判断：哪些页面可以照搬，哪些必须重写，哪些不做。

输出 docs/<DISEASE>-DOMAIN.md，包含：分类层级、诊断依据、分期、评分、
疗效标准、指标字典（标明哪些能画趋势、哪些是分类变量）、数据实体草案。
```

## 第三轮：导航与场景

```
给出 8 项一级导航，并说明每项为什么在这个位置（与真实决策顺序对齐）。
写 12 个场景（谁/何时/想回答什么/给什么/不给什么/落在哪页）。
每个场景必须有一句"不给什么"，否则会滑向诊断建议。
```

## 第四轮：Spec

```
写 docs/SPEC.md：三道闸口与状态、目标与非目标、一期/二期/不做清单、
信息架构、四条主线、验收 A1–A30（含布局与文案红线）、发布三层验证、风险表。
所有"未验证"必须写明，不得写成已通过。
```

## 第五轮：Demo

```
做 prototypes/v0.1：零依赖 HTML/CSS/JS，8 页 + 子页，5 套演示画像。
硬要求：
- 版本号三处同源（顶栏/页脚/关于）
- 真 3D 翻转卡（正反面绝对叠放，固定高度）
- 图表：多序列归一化、治疗条与数据区分离、末点标签防重叠
- 分类变量不画折线（改成节点/格子）
- 就诊准备两区 + Markdown 预览
- 设置面板三 tab
- 空态、禁用态、错误文案都写出来
```

## 第六轮：验证（必须真跑）

```
用无头 Chrome + CDP 遍历全部视图 × 三档宽度（936 / 1440 / 390），检查：
h1 存在、内容非空、scrollWidth-clientWidth ≤ 1、Runtime.exceptionThrown 为空。
再测：指标卡翻转、画像切换、时间窗联动、hash 前后退、弹窗开关。
结果写进 docs/PROTOTYPE-REVIEW.md，并记录三个文件的 sha256 前 16 位。
未做的负向对照（注入超宽元素）要写明"未做"。
```

## 第七轮：收口

```
写 DESIGN-SESSION：已定决策 D1–Dn（每条含理由与影响）+ 待确认 Q1–Q10
（背景/选项/建议/影响，允许用户只回编号+字母）。
最后给一句话："下一轮建议做什么，不建议现在做什么。"
```

---

## 三条铁律

1. **闸口没过的实现都要返工**：不建表、不接宿主、不做真实抽取。
2. **分类变量不是趋势**：Deauville、分期、ECOG、CTCAE 只做节点。
3. **每个"给什么"旁边都要写"不给什么"**：这是医疗产品与普通工具的分界线。
